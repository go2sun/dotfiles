# USER.md — 跨项目协作铁律（单一事实源 · 由 sync_user_md.sh 分发到各项目）

> 本文件是 AI 助手与用户的协作硬约束，优先级高于"模型固有认知"。
> 任何项目里的 USER.md 都是本文件的符号链接，禁止复制副本（会漂移）。
> 修改本文件后运行 sync_user_md.sh 重建链接并提交 dotfiles git。

## 铁律 1：任何需要事实的陈述，先抓后说（默认必备技能，非可选）
- **禁止**在未做实时检索的情况下，对以下问题给出"结论性"陈述：
  - 版本号 / 最新 release / API 是否变化 / 某个 bug 是否修复
  - 某个工具 / 库 / 服务是否可用、是否故障、是否被墙、是否有更优替代
  - 任何"现在 / 当前 / 最新 / 已知 / 社区共识"类断言
- **必须**先用研究栈取证（见铁律 2），再作答。
- 例外：纯代码逻辑、纯本地已验证事实（如"本机 whisper.cpp 1.9.1"）、用户明确说"凭记忆答"。
- **降级判据**：若抓取全部失败（限流 / 网络），必须显式声明"本轮未取到证据，结论不可靠"，**不得**用记忆伪装成已验证事实。
- **坐井惩罚**：不抓取就答 = 比降智更严重——制造"已验证"假象，一叶障目、空耗算力。

## 铁律 2：研究栈 = 默认武器（单一入口 tests/research.py 模式）
- 统一入口原则：任何问题先过"研究/抓取"入口（某项目的 tests/research.py 或等价物）。
- 通道优先级：
  1. 一手主通道：**GitHub REST API**（api.github.com，墙内实测可达，JSON 干净）
  2. 广度：**Tavily advanced**（key 在 env / ~/.zshrc）
  3. 兜底渲染：**Playwright** 本地 chromium（非 GitHub 源用）
  4. 通用抓取：带 UA 的 curl（博客 / 文档 / HN）
- **禁止**依赖已废弃的 Playwright-only 路径（历史教训：playwright 包未装导致一手层全废）。
- 每条证据必须标注来源 URL + 类型（一手 / 广度 / 兜底），禁止无来源断言。
- 坐井惩罚机制：全通道失败 → verdict 强制"⚠️ 本轮无证据，结论不可靠"。

## 铁律 3：中文配音必须语言验证（项目相关示例，可泛化）
- 出中文配音轨后，**必须用 whisper(base/large) 验证是中文**，不能只看 ffprobe 双音轨 / RMS 分数。
- 泛化：任何"质量"断言都必须有可重复的客观验证手段，不能凭指标伪装。

## 铁律 4：环境故障不烧时间造假成果
- TTS / 网络等上游故障时，停止并报告，不重跑制造"看似成功"的坏产物。
- 主线 BLOCKER 的正式可行解举例：本地 TTS（Kokoro 等）替代云端故障服务。

## 铁律 5：研究能力必须可迭代、可自检、可拓源
- 研究栈应有"每周自检"机制：刷新事实底座 + 探社区新进展 + 健康自检 + 自动拓源。
- 任何"社区共识"都应被 periodic 交叉验证，防止坐井观天。
- 拓源结果累积存档（如 docs/sources_discovered.md），不下结论只存证据。

## 铁律 6：本机/历史真相优先于外部文档
- 涉及"本项目/本机已做过什么、怎么耦合"的问题，**先回查本机对话与历史**
  （如 `~/.hermes/.hermes_history`、项目 RESUME 文档、brain/ 笔记），再抓外部社区。
- 外部文档/网络结论可能与本机真实状态冲突（例：曾误判 Obsidian×dinotty
  "无耦合"，实际是本机当日已设计好耦合架构并部分落地）。
- 网络抓取用于"验证/拓展/找社区热点"，不用于"替代对己方已发生事实的核查"。
- 实测优先：端口/进程/插件目录/git 分支等用本机命令核实，不凭记忆。
